# 0.4.0-beta.2 수정 검증 — 2026-10-28

Windows11 build26200 / Qt6.8.3 / MSVC19.38 / FFmpeg9.0.2. 모든 검사는 소리를 재생하지 않았다.

## 원인과 변경

- 최적 화면의 MouseArea가 타이머 열 안에만 있었다. 배경 전체의 MouseArea를 버튼 뒤에 배치해 여백·상태·타이머·용량 영역에서도 이동을 시작하고 버튼은 자신의 클릭을 받도록 했다.
- 녹화 완료가 editorRequested를 직접 발생시켰다. recordingReady로 분리하고 이름·폴더·실제 파일 크기·편집·저장을 가진 저장 창을 먼저 연다. 편집 닫기는 저장으로 돌아온다. 이미 생성한 세션 파일은 ‘나중에’나 창 닫기로 삭제하지 않는다.
- 다른 위치에 저장할 때는 작업 스레드로 복사한다. 새 파일은 같은 디렉터리 임시 파일을 rename하고, 기존 파일은 명시적 확인 후 QSaveFile로 교체한다. 실패 시 원본을 보존하고 직접 쓰기 fallback은 사용하지 않는다.
- 최대화·최적 모드 전환이 일반 창 크기를 덮어쓰지 않게 저장했다. 최대화 버튼과 최대화 상태 제목 표시줄 이동은 저장한 일반 크기를 복원한다.
- 대기 상태에서 이전 프레임 수로 타이머를 표시하던 것을 숨기고 elapsed 표시값을 00:00:00으로 초기화한다. 녹화/일시정지 중에만 타이머와 예상 크기를 표시한다.
- 예상 파일 크기는 실제 인코딩된 중간 영상 바이트 + 녹화 시간에 따른 최종 192 kbit/s AAC 트랙 크기다. 다중 소스의 기본 믹스 트랙도 포함한다. 복구용 원본의 전체 디스크 점유량이나 RAM 사용량과 구분한다. 중간 Matroska 클러스터를 1초 간격으로 flush한다. 컨테이너·인코더 버퍼 때문에 추정 오차가 남는다.
- TransportButton의 구조체 속성 sourceSize.height 자기 참조 바인딩 경고를 Qt.size 지정으로 없앴다.

## 결과

- 로컬 CTest 11/11 통과. 기존 10개에 window_controls 추가. 저장 복사·대상 충돌·동의 후 교체·실패 시 원본 보존 및 0/1/2 오디오 소스 크기 계산을 core에서 검증한다.
- window_controls는 최대화 버튼 복원과 최대화 상태 이동 시작을 호출해 760×680 복원, 400×104 최적 모드 전환/복귀, 세 곳의 배경 여백에 실제 Qt 마우스 입력 전달을 확인한다. offscreen 검사와 Windows 네이티브 창 검사 모두 통과했다. 물리 포인터로 드래그하는 수동 인수 시험과는 구분한다.
- tools/test-windows-region.ps1: 실제 WGC로 자기 색상 창의 160×120 영역을 녹화. 이동·일시정지 후 0.3/1.0/1.8초 표본은 빨강/파랑/빨강 각각 100%, 오디오 트랙 0. 녹화 중 예상 크기 갱신과 버튼 겹침 없음도 확인했다.
- 같은 검사에서 정지 후 저장 창 먼저 열림, 편집기 닫힘, 대기 타이머 숨김/00:00:00, 저장 창의 편집 버튼으로만 편집 열림, 편집 닫기 후 저장 복귀, 파일 이름 변경 후 저장 성공을 확인했다. artifacts/region-result.json의 saveFlowVerified 및 idleTimerVerified가 true다.
- 자체 무음 영상의 편집 회귀 검사에서 새 파일과 덮어쓰기 모두 0.5–2.5초를 2.0초로 저장하며 새 파일 저장 시 원본 해시를 보존했다.

## 범위

CPU 프레임 복사, 미구현 기능, 공통 하드웨어 조건, 현재 프로세스 캡처 단위, 실제 장비 미검증을 README에서 구분했다. 이번 변경이 GPU 직접 캡처·HDR·앱 내부 개별 통화자 분리를 구현한 것은 아니다. 실제 Mac의 권한·녹화·장치 시험과 장시간 고부하 시험은 여전히 별도 검증 대상이다.
