# 영역 녹화와 이동 — 0.3.0-alpha.3

1. 새로고침 후 **영역**을 선택하고 녹화할 디스플레이를 고릅니다.
2. **영역 선택**을 누르고 화면에서 드래그합니다. 선택한 부분만 캡처하며 출력 해상도도 해당 영역의 실제 픽셀 크기로 맞춥니다. 최소 64×64이며 H.264를 위해 홀수 크기는 1픽셀 줄여 짝수로 맞춥니다.
3. 남아 있는 테두리의 이동 손잡이 또는 가장자리를 드래그해 위치를 옮깁니다. 내부는 클릭이 통과하므로 원래 프로그램을 조작할 수 있습니다.
4. 녹화 중과 일시정지 중에도 같은 방법으로 이동할 수 있습니다. 파일 크기·오디오·타임라인은 유지하고 캡처 위치만 바뀝니다. 테두리는 녹화 중 빨강, 일시정지 중에는 황색입니다.

이동 범위는 선택한 디스플레이 내부입니다. 다른 모니터나 다른 크기는 녹화를 끝내고 다시 선택합니다. 화면 배율은 논리 좌표와 실제 픽셀 사이에서 변환하며 Windows는 디스플레이 나열 순서 대신 실제 모니터 핸들로 연결합니다.

이동 손잡이와 테두리는 선택 영역 바깥에 배치합니다. 위쪽 공간이 부족하면 손잡이가 아래쪽으로 이동하고, 가장자리도 드래그할 수 있습니다. Windows에서는 영역 테두리 창을 캡처에서 제외하도록 설정합니다.

선택 후 해상도 프리셋을 직접 바꾸면 명시한 크기로 확대/축소할 수 있습니다. 기본 동작은 선택 영역의 원본 크기입니다. macOS 구현은 CI 빌드/자동 검사와 물리 장비 검증을 구분합니다.

## 무음 검증

`tools/test-windows-region.ps1`은 사용자의 데스크톱이나 마이크 대신 앱이 만든 정적인 빨강/파랑 창만 캡처합니다. 테스트 톤을 재생하지 않습니다. 실제 QML 테두리에 마우스 이벤트를 전달해 녹화 중 및 일시정지 중 드래그를 확인합니다. 영상은 160×120로 유지됐고 0.3초/1.0초/1.8초 프레임의 픽셀이 각각 100% 빨강/파랑/빨강으로 판정됐습니다. 영역 밖의 초록 테두리와 반대쪽 내용은 포함되지 않았으며 오디오 트랙은 0개입니다.

정적인 소스에서도 새 프레임 알림을 기다리지 않고 이동이 적용되도록 Windows는 마지막 staging 텍스처를 다시 잘라 내고, macOS는 캐시된 전체 프레임에서 새 영역을 만듭니다. 녹화 세션이나 오디오 캡처를 재시작하지 않습니다.

코어 검사는 음수 위치의 모니터, 150% 배율, 짝수 크기 변환, 화면 밖 선택 거부, 경계에서 크기를 유지한 이동을 확인합니다. 혼합 DPI와 물리 Mac에서의 수동 인수 시험은 별도로 남아 있습니다.
