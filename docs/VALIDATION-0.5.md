# 0.5.0-beta.1 검증

2026-10-28–29. Windows11 / NVIDIA RTX4070 (32.0.16.1088) / MSVC19.38 / Qt6.8.3 / FFmpeg9.0.2. 검사는 모두 무음으로 수행한다.

## GPU 직접 경로

Windows의 D3D11 캡처 텍스처를 GPU VideoProcessor로 크기·영역 변환 및 NV12 변환하고, Media Foundation 하드웨어 H.264 인코더에 DXGI 미디어 버퍼로 전달한다. 하드웨어 활성화 플래그만으로는 소프트웨어 fallback이 가능해 실제 인코더의 하드웨어 URL 속성도 확인하고, 없으면 실패한다. FFmpeg는 이 경로에서 원시 BGRA를 받지 않고 이미 인코딩된 영상과 오디오 트랙을 결합한다.

macOS는 ScreenCaptureKit의 CVPixelBuffer를 유지하고 Metal/CoreImage 및 AVAssetWriter/VideoToolbox 하드웨어 요구 옵션으로 처리한다. 이 구현의 실제 Mac 권한·캡처·성능 시험은 별도로 필요하다.

두 플랫폼 모두 캡처 콜백의 매 프레임 CPU 읽기를 없앴다. 미리보기와 CPU 경로가 프레임을 요구할 때만 지연 읽기하며, 소스가 바뀌지 않았으면 캐시를 재사용한다. Native GPU의 작은 녹화 창에서는 미리보기 읽기도 멈춘다. 프레임 복제 횟수는 GPU 경로에서 측정하지 않으므로 session.json에 null로 기록한다.

- 640×360/30의 합성 GPU 프레임 세 개로 실제 하드웨어 인코더 검사 통과. 화면·마이크·스피커를 열지 않는다.
- 실제 WGC의 자기 색상 창, 160×120/30 녹화에서 영역 이동·일시정지·재개·저장을 확인했다. 0.3/1.0/1.8초 표본은 빨강/파랑/빨강 각각 100%이고 오디오는 0개였다.
- GPU 인코더에서 0.45–2.45초 검사 구간의 CPU 픽셀 읽기 0회를 확인한다. 초기 연결·미리보기와 정지 후 읽기는 별개다. 이는 앱의 readback 계측이며 전체 CPU 사용률 0%나 모든 드라이버 내부 복사 제거를 뜻하지 않는다.
- 기존 CPU/FFmpeg 경로는 선택 가능하며, 직접 GPU 실패 시 조용히 CPU로 바꾸지 않는다. 해상도/FPS는 실제 하드웨어·드라이버 처리량에 제한된다.

재현: `tools/test-windows-region.ps1 -NativeGpu`. `region-result.json`, `region-verification.json`, Recovery의 session.json/원본/완성 영상을 확인한다. 실제 작업 기록·미디어·로그는 Git에 포함하지 않는다.

## 업데이트

자동 검사 13개에 update_catalog 및 update_transaction이 포함된다. update_catalog는 버전 숫자/안정·베타 순서, 이전 버전 차단, 채널 분리, 잘못된 OS/아키텍처·자산 URL·크기·해시·초안 거부를 검사한다.

update_transaction은 고유한 `FARecorder update 검사 & …` 경로의 별도 앱만 사용한다. 정상 교체·사용자 파일 보존·이전 버전 백업, 잘못된 체크섬, ZIP 상위 경로, 새 앱 실행 실패 후 복구, 사용자 파일 충돌, 취소를 검사한다. 실제 설치된 앱과 사용자 녹화는 건드리지 않는다.

초기 검사에서 이미 종료된 PID의 이미지 조회 경합을 발견했다. 종료 여부를 먼저 확인하고, 살아 있는 PID에 대해서만 앱 경로 일치를 요구하도록 수정했다. GUI 준비 상태 검사는 메시지 루프가 있는 숨겨진 자체 테스트 앱으로 검증한다. 앱은 준비 성공 신호를 받은 뒤 종료하며, 실패·취소 시 열린 상태를 유지한다.

실제 GitHub 조회는 `--update-check-test`로 검증한다. 온라인 검사를 CTest 필수 항목으로 넣지는 않는다. 실제 앱의 새 공개 버전 간 교체는 후속 버전이 있어야 하며 현재 트랜잭션 시험은 별도 앱의 실제 파일 교체·재실행으로 수행한다.

## 유지한 동작

기본/상세/최소 크기 UI, 실제 이름 오디오 선택기, 도움말·라이선스·업데이트 메뉴, 창 복원, 소스 목록 갱신, 설정 마이그레이션, 실제 CPU 인코더 검사와 코어 오디오 타임라인/믹서 검사를 유지한다. 영역 검사에는 저장 우선·파일명 변경·평면 저장·미저장 종료 취소 및 Application Quit 경로 확인을 포함한다.
