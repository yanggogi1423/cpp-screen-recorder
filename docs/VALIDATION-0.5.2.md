# 0.5.0-beta.2 종료 처리 검증

2026-10-31. Windows / Qt 6.8.3 / FFmpeg 9.0.2.

## 원인

긴 녹화의 종료 후 영상은 복사하고 WAV 독립 트랙과 전체 믹스를 AAC로 인코딩한다. 기존 UI는 모든 단계를 ‘저장 중’으로만 표시했으며 FFmpeg 진행 상태를 읽지 않았다. 실제 작업 로그에서 약 86분 영상의 3개 오디오 트랙 결합에 약 112초가 걸렸고 정상 종료한 사례를 확인했다. 최종 MP4의 영상과 3개 AAC 트랙 길이는 모두 약 5150.57초였다. 사용자 미디어와 원본 로그는 저장소에 포함하지 않는다.

추가로 기존 코드는 결합 전체에 고정 300초 제한을 적용했다. 진행 중인 더 긴 녹화도 중단할 수 있었다. 이 제한을 실제 미디어 타임스탬프/출력 크기/수정 시각의 300초 무진행 감시로 바꿨다. 단순한 stderr 출력만으로 제한 시간을 초기화하지 않는다. 로그는 매 수신 시 기록한다.

## 회귀 검사

- `recording_finalization`: 분할 수신, CRLF, FFmpeg microseconds 단위, 잘못된/역행 타임스탬프, 종료 전 99% 상한 확인.
- 같은 테스트에서 실제 자식 프로세스의 전체 실행 시간이 무진행 제한보다 길어도 계속 진행하면 성공하는지, 정지한 프로세스는 종료되고 실패 코드가 성공으로 표시되지 않는지 확인한다.
- FFmpeg가 있으면 OS 캡처 없이 합성 검정 영상 및 무음 PCM 2개를 생성하고 RecordingSession의 종료·진행률·최종 저장을 실행한다. 완성 영상과 전체 믹스/독립 오디오 2개를 모두 null 출력으로 디코딩한다. 음원 재생·스피커·마이크 접근은 없다.
- `qml_finalizing`: 720×640 화면에서 진행 상태가 보이고 아래로 잘리지 않으며 녹화 타이머가 숨겨지는지 검사한다.

테스트는 사용자 녹화 파일을 수정하지 않는다. 장시간 후처리가 즉시 완료되도록 인코딩 구조 전체를 변경한 것은 아니다. Windows GPU 인코더의 동기 Finalize나 OS 장치 API 자체의 별도 드라이버 정지는 이번 관측 원인이 아니며 해결됐다고 주장하지 않는다.
