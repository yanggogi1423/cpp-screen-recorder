# 0.5.2-beta.1 저장 후 복구 정리 검증

2026-11-25.

## 변경과 보존 경계

기존에는 파일 저장 성공 후 `Recovery`의 원본 영상과 독립 WAV를 유지했다. 최종 파일 복사·원자적 반영이 성공한 뒤 같은 저장 작업 스레드에서 해당 세션만 삭제하도록 변경한다. 앱이 만든 소유권 marker, 설정된 Recovery root의 바로 아래 세션인지, 링크/junction이 없는지 확인한다. 최종 파일을 Recovery 안에 저장하는 요청은 거부한다. 정리 실패는 최종 저장 성공과 구분해 경고하며, 기존 메시지 처리에 따라 자동 종료 의도를 해제한다.

녹화를 중지한 시점이나 편집 중간 저장만으로 원본을 지우지 않는다. 미저장·실패·덮어쓰기 취소는 보존한다. 외부에서 연 영상에는 현재 녹화 세션의 정리를 적용하지 않는다. 예전 marker 없는 복구 폴더도 자동 삭제하지 않는다.

## 검사

- `recovery_cleanup`: 최종 저장 후 삭제 및 최종 파일 bytes 보존, 덮어쓰기 승인 전 보존·승인 후 정리, 실패 보존, Recovery 안 저장 거부, 식별되지 않은 폴더 보존, root 이탈 거부, 편집본 저장 후 원본 정리.
- 파일시스템이 디렉터리 symlink 생성을 허용하면 외부 데이터를 가리키는 링크를 둔 복구 폴더도 보존하는지 검사한다. OS가 생성을 거절하면 그 항목은 SKIP으로 기록한다.
- 실제 Windows 자기 창 영역 녹화 검사는 저장 후 세션 폴더 부재를 확인하고 결과에 `recoveryCleaned`를 기록한다. 최종 영상은 FFmpeg로 디코딩해 길이·크기·색상 구간을 검증한다. 소리 재생이나 마이크 접근은 없다.
- 저장·정리와 무관한 기존 무음 CTest 및 실제 설치·제거·재설치 보존 검사를 유지한다. 패키저는 앱 로컬 CRT 복사 후 불필요한 `vc_redist.x64.exe`만 제외한다.

## 요청된 기존 데이터 정리

사용자 요청으로 실행 중인 앱과 링크가 없음을 확인한 실제 Recovery 9.954GiB/79파일을 삭제했다. 별도의 최종 영상 폴더는 유지했고 전후 파일 크기·수정 시각이 같음을 확인했다. 경로·파일별 개인정보를 포함할 수 있는 원본 로그는 공개 소스에 포함하지 않는다.

로컬 개발 SDK는 저장 공간 정리 요청으로 제거했다. 새 버전은 GitHub CI에서 빌드하고 배포 파일만 내려받아 설치·실제 저장을 확인한다. 물리 Mac 녹화 검증은 macOS CI와 구분한다.
